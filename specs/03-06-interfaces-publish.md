# Specs 03–06 — Web interfaces and publication

All pages are static HTML in `site/`, share `site/style.css` and a nav bar, load data from `site/data/*.js`
(generated by `python project2.py build`), work on GitHub Pages and from `file://`, and adapt to phone width
and dark mode. Charts use Chart.js 4.4.1 from cdnjs.

## 03 — Findings dashboard (`site/index.html`)
- **AC-3.1** Shows headline KPIs: schools, documents, % schools whose courses permit or encourage AI, % documents with collaboration framing.
- **AC-3.2** Has charts for RQ1 (stance distribution), RQ2 (sentiment by document type), RQ3 (collaboration framing), RQ4 (SE courses), RQ5 (R1 vs. non-R1, public vs. private).
- **AC-3.3** Has a searchable, filterable school table and a document/evidence explorer that shows source links and quotes.
- **AC-3.4** States method, validation (gold accuracy, κ) and limitations on the page.

## 04 — Validation explorer (`site/validation.html`)
- **AC-4.1** Lists every logged test result with search and filters (phase, outcome, run).
- **AC-4.2** Shows each test's source code and docstring next to its result.
- **AC-4.3** Maps spec acceptance criteria to the tests that cite them, and flags criteria with no test.
- **AC-4.4** Shows ad-hoc checks and the human review steps.

## 05 — Timeline and token usage (`site/timeline.html`, `site/tokens.html`)
- **AC-5.1** The timeline merges `logs/timeline.jsonl` events and git commits, filterable by actor (human/Claude), kind and phase.
- **AC-5.2** The token parser deduplicates requests by requestId and sums input/output/cache tokens exactly.
- **AC-5.3** The token page breaks usage down by session, activity, phase and practice (fresh/clear/compact), with cache vs. fresh input shown separately.

## 06 — Publication
- **AC-6.1** `README.md` explains the project, how to reproduce it, and links every interface.
- **AC-6.2** The repository is git-initialized with all source, specs, logs and generated site data committed; `site/` is ready for GitHub Pages (`.nojekyll`).
- **AC-6.3** `docs/evaluation.md` gives the human a template, with data pointers, for evaluation and reflection.
